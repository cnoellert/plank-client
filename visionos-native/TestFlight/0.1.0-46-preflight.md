# Vision Pro checkpoint: 0.1.0 (46)

The accepted development runtime is Client `d0056978e823a7f9a999efe9336cdb155aa61f35`.
This follows the published build 37 checkpoint and preserves its audio, session
controls, mouse input, bitrate, hardware decoder recovery and diagnostics.

## Product changes

- Setup registers a drawing Relay through authenticated, model-independent
  enrollment. The Client keeps the drawing identity pinned; a name, address or
  discovered Bluetooth peripheral is not approval.
- Each registered Relay offers Automatic, Bluetooth or Network drawing.
  Bluetooth carries the existing raw HID protocol and reverse controls through
  the managed Relay's L2CAP bridge. Setup testing and Client drawing remain
  separate capture owners.
- A new desktop transport resets retained tablet endpoints before attachment.
- A tablet that disappears after successful attachment remains recoverable
  after the availability grace expires. Mouse and keyboard become available
  during the outage; returning tablet input waits for descriptors and Host
  acknowledgement. Explicit opt-out and initial absent-tablet startup retain
  their previous behavior.

## Verification and field acceptance

The live outage policy and Wacom preflight checks pass with Swift assertions
enabled. A mutation restoring permanent bypass fails the outage checks.
Package CI passed 37 managed and 26 raw tests on both amd64 and arm64, plus
independent clean installation, reinstallation and removal checks:
[package run 37371157044](https://github.com/cnoellert/plank-avp-relay/actions/runs/37371157044).

Development-device acceptance covers Setup-mediated enrollment, explicit
Bluetooth and Network drawing with pen controls and reconnect, complete package
migration, sleep/wake, USB/Bluetooth tablet switching, a full tablet outage and
return without desktop reconnect, and Relay service restart recovery.

Bluetooth drawing also passed while all Relay non-loopback network interfaces
were temporarily down, independently verified before automatic restoration.
The tablet was USB-connected during that isolation test. Simultaneous wireless
tablet input and an isolated Relay Bluetooth drawing link were not separately
qualified. These checks are development-device evidence, not fleet coverage.

## Remaining limits

- Small periodic playback stutters remain unresolved.
- The previously observed Host input receive queue overflow is not fixed here.
- Development and App Store Release builds are distinct artifacts. Archive,
  signing, symbols, payload inspection and Apple upload/availability results
  are recorded separately; this document does not imply an upload completed.
- No credentials, device identities, pairing stores or operator captures are
  included in this publication.
